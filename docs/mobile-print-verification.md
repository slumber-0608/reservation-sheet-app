# スマートフォン印刷修正・検証記録

確認日: 2026年11月6日（日本時間）

## 調査結果と変更

`ReservationSheetApp.tsx` のクリック処理は `requestAnimationFrame(() => window.print())` へ印刷を遅延していた。`PrintAllSheets` は全日分を常時DOMに生成しており、印刷前のフレーム待機は不要。ユーザー操作との関連を維持するため、クリック処理で同期的に `window.print()` を呼ぶよう変更した。

この遅延だけが実機不具合の原因であると断定する実機証拠はない。Android WebViewはHTML内のJavaScriptによる印刷開始をサポートしないと公式資料に明記されており、直接呼び出しに変えるだけでは全環境をカバーできない。

- Safariの共有→プリント、Android Chromeの⋮→共有→印刷をUIへ常時表示。
- APIが例外を投げる・存在しない場合は通知を表示。APIが無反応の場合にも手順を読めるようにし、成功・失敗の推測タイマーは設けない。
- アプリ内ブラウザからSafari/Chromeへ移る手順と、年月・追加休日の再確認を案内。別ブラウザへlocalStorageが引き継がれない場合を考慮。
- OS標準の印刷プレビューからPDFを保存する方法を案内。既存の印刷DOM/CSSを利用できるため、独自のPDF生成機能は追加しない。
- 印刷CSS、平日20行・休日21行の生成、休日判定、追加休日の保存形式は変更していない。
